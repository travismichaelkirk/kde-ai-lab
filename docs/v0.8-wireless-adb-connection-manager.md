# KDE AI Lab v0.8 — Wireless ADB Connection Manager

## Purpose

Provide a repeatable, manually invoked Fedora utility for discovering,
verifying, and restoring Wireless ADB connectivity to the Pixel 11 Pro.

Reduce the need to manually identify Android's changing Wireless
debugging connection port.

## Scope

Script: scripts/diagnostics/adb-connect.sh

Run: ./scripts/diagnostics/adb-connect.sh

The connection manager:

1. Discovers the Pixel's TLS Wireless debugging service through Avahi.
2. Identifies the expected device using its configured serial number.
3. Checks existing ADB transports.
4. Verifies a responsive connection by querying the device serial.
5. Avoids reconnecting when a verified connection already exists.
6. Attempts recovery when no verified connection is available.
7. Verifies device identity after recovery.

The utility runs on demand. It is not a background service.

## Dependencies

- Fedora Linux with Bash.
- Android Debug Bridge (ADB).
- Avahi service discovery and the avahi-browse command.
- The Pixel and Fedora host on a network permitting discovery and ADB.
- Wireless debugging enabled on the Pixel.
- An existing, authorized ADB pairing.

The expected Pixel serial number is currently configured in the script.

## Verified Functionality

The following tests passed:

- Bash syntax validation.
- ShellCheck static analysis.
- Discovery of the Pixel's TLS Wireless debugging endpoint.
- Recognition of an existing IP-based ADB connection.
- Recognition of an existing mDNS-named ADB connection.
- Verification of an existing connection using the device serial.
- Avoidance of unnecessary reconnection.
- Recovery after all active ADB transports were disconnected.
- Device serial verification after successful recovery.
- Direct execution using executable file permissions.

Full disconnection and recovery succeeded both before and after
the connection-verification improvements.

## Error Handling

The script reports:

- Missing avahi-browse dependency.
- Avahi discovery timeout or failure.
- Absence of the expected Pixel TLS discovery service.
- Failure to list ADB connections.
- Failure to establish or verify a recovered connection.
- A recovered device identity that does not match the expected serial.

These error paths have not all been independently fault-tested.

## Security and Privacy

- ADB connections require Android authorization.
- The script checks the device serial before accepting a connection.
- Serial verification is an identity consistency check, not an
  independent cryptographic security assessment.
- The script does not bypass Android authorization or work-profile
  isolation.
- The script does not modify Tasker tasks or profiles.
- The script does not change the existing ADB TCP port 5555 configuration.
- The script does not restart the ADB server.
- The script does not change LADB configuration.

## Known Limitations

- Wireless debugging must already be enabled on the Pixel.
- Existing ADB authorization and pairing must remain valid.
- The Pixel must be reachable over the network.
- Avahi discovery must successfully advertise and resolve the TLS service.
- The script currently targets one configured Pixel serial number.
- Recovery cannot remotely enable Wireless debugging.
- Recovery cannot restore revoked Android pairing authorization.
- Network changes or Android updates may require additional testing.
- Discovery failure and timeout scenarios need further fault testing.

## Operating Policy

- Invoke the connection manager manually when needed.
- Verify device identity before trusting a recovered connection.
- Preserve existing Tasker, LADB, and port 5555 workflows.
- Respect Android work-profile security boundaries.
- Validate changes before committing milestone releases.
