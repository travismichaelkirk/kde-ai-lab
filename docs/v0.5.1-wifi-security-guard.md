# KDE AI Lab v0.5.1 — Wi-Fi Security Guard

## Purpose

Automatically disable the Tasker HTTP Bridge when the Pixel
disconnects from the trusted home Wi-Fi network.

The bridge remains disabled after reconnecting and requires
deliberate manual activation.

## Configuration

### HTTP Bridge

Profile: KDE AI Lab HTTP Bridge

- Event: HTTP Request
- Port: 8765
- Only On WiFi: Enabled
- Additional State: WiFi Connected
- Trusted SSID: home
- Associated task: KDE AI Lab Test
- Normal operating state: Disabled

### Security Guard

Profile: KDE AI Lab - WiFi Security Guard

- State: WiFi Connected
- SSID: home
- Invert: Enabled
- Profile status: Enabled
- Associated task: KDE AI Lab - Disable Bridge

### Shutdown Task

Task: KDE AI Lab - Disable Bridge

- Action: Profile Status
- Name: KDE AI Lab HTTP Bridge
- Set: Off

The shutdown task never enables the HTTP Bridge.

## Verified Tests

1. Unauthenticated HTTP request returned 401.
2. Authenticated HTTP request returned 200.
3. Disconnecting from home Wi-Fi automatically disabled the bridge.
4. Reconnecting to home Wi-Fi did not reenable the bridge.
5. Fedora connection attempt with the bridge disabled failed.
6. HTTP Status 000 confirmed no HTTP response from the tested endpoint.
7. Updated Tasker project export passed XML validation.

## Known Limitations

- The safeguard reacts to Tasker's Wi-Fi state detection.
  Shutdown is not necessarily instantaneous.
- The trusted network is identified by SSID, not cryptographic
  network identity.
- The HTTP listener uses unencrypted transport while enabled.
- Manually enabling the bridge while already disconnected from
  home Wi-Fi was observed to leave the profile enabled.
- The additional WiFi Connected context has not yet been proven
  to close the underlying listener on an untrusted network.
- Behavior after phone reboot or Tasker restart has not yet
  been verified.
- The HTTP Bridge authentication token is not included in the
  Git-tracked Tasker project backup.

## Operating Policy

- Keep the Wi-Fi Security Guard enabled.
- Keep the HTTP Bridge disabled except during development.
- Manually enable the bridge only while connected to home Wi-Fi.
- Allow Tasker to disable the bridge when leaving home.
- Never automatically reenable the bridge upon returning home.
- Do not expose port 8765 through router port forwarding.
